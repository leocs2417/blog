Vue 中，nextTick 的实现原理

Vue源码

Vue 的异步更新队列依赖 nextTick。当你修改数据后立刻去读 DOM，往往拿到的是更新前的内容——因为 Vue 的 DOM 更新是异步批处理的。本文结合事件循环机制，从源码角度拆解 nextTick 的降级策略与使用场景。

为什么需要 nextTick

Vue 在观测到数据变化时，不会立即更新 DOM，而是把 watcher 推入一个队列，在下一个 tick 中统一 flush。这样可以避免同一个 tick 内多次修改数据导致的重复渲染。

同一个 watcher 在一个 tick 中只会被加入队列一次，这是去重后的结果。

源码中的降级策略

nextTick 的本质是「微任务优先」的异步函数，其实现按环境能力逐级降级：

  • 优先使用 Promise.then（微任务）
  • 降级到 MutationObserver
  • 再降级到 setImmediate / MessageChannel
  • 最后兜底 setTimeout(fn, 0)
// 简化后的 nextTick 实现 const callbacks = [] function nextTick(cb) { callbacks.push(() => cb()) if (!pending) { pending = true Promise.resolve().then(flushCallbacks) } }

使用场景

典型场景是「修改数据后立即操作 DOM」：更新数据后，在 nextTick 回调里读取或测量 DOM，就能拿到更新后的结果。
